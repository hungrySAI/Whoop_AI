# 本地看板使用说明

V1 日常使用指南。首次接入参考 [创建应用与本地接入](WHOOP_SETUP.md)，返回 [项目首页](../README.md)。

已完成本地授权后，双击 [打开看板](../scripts/open-dashboard.command)。服务就绪后自动打开
[本地看板](http://127.0.0.1:8766)，启动成功后可关闭终端。重复打开会复用同项目、同数据库的服务。
看完后可双击 [停止看板](../scripts/stop-dashboard.command)；同步进行中会提示稍后停止，保护原断点。
关闭浏览器本身不会停止本机服务，但不会新增定时采集；电脑关机后服务退出，下次需要时再打开。
本批不安装登录启动项或后台定时任务。

对应命令：

```sh
uv run whoop-copilot --environment real dashboard-open
uv run whoop-copilot --environment real dashboard-stop
```

仍可用 `dashboard` 命令前台运行并按 Ctrl+C 停止。端口被其他程序或旧版服务占用时，
启动器不会打开或终止那个程序；先自行停止旧服务，或用 `--port` 选择其他端口。
无需重新输入 Client Secret；本机钥匙串仍可能显示系统访问提示。

- 每日摘要展示所选窗口内最近的恢复分、睡眠表现和周期负荷，包括未评分状态。
  各项标注日期与「今日/此前记录」，今天按 UTC 起点归属；没有今天记录时直接展示并标明历史，
  不当作同步失败或佩戴判断。睡眠包含可能的小睡，未结束周期的当前负荷明确标注。
- 每项旁边展示近 7/30 天前后半段有效观测的均值变化，复用原注册统计；两段各至少 2 条才比较。
  样本不足显示数量，保留现有官方记录，不要求先积累 30 天。百分比差值使用百分点，
  不把负荷升高自动称作改善。「查看趋势与依据」进入对应指标，来源按钮继续查看具体官方记录。
- 趋势支持 HRV、静息心率、恢复分、睡眠表现、周期负荷与训练负荷；后两项不合并。
- 「恢复回看」按周期起点的 UTC 日期查看最近 7/30 天，每页 10 个周期，选中一条即可查看关联详情。
  恢复分、HRV、静息心率与关联睡眠的表现、效率、一致性、呼吸率均来自已有官方观测。
  只沿 WHOOP 的周期/睡眠 ID 关联，允许睡眠跨筛选边界；较晚小睡不会取代指定睡眠。
  缺项或版本不一致会提示暂不可组合，未评分仍保留状态；再次同步不保证能补齐关联。
  生理周期不等于日历日，周期负荷仍在进行时明确标注；并列记录不说明本周期负荷导致这次恢复。
- 「周回顾」默认上个完整 UTC 日历周，可选择本周及此前 11 周；均值来自本机当前保留的有效观测。
  所选完整周与前一完整周各至少 2 条有效观测才比较，本周只显示截至现在的进度。
  日历周结束不保证采集完整，记录日数不等于佩戴天数；恢复随周期起点，睡眠可能包含小睡，
  周期负荷与训练负荷分别取均值，不相加成新周评分。各项可查看两周记录与来源，每页 30 条。
  官方修正、删除或到期会改变重新读取的结果，周回顾不是永久报告副本。
- 选周只读取本机数据。「同步并补取」以最近 30 天视图为起点，结合成功请求记录向前扩展，
  更早周是否被查询取决于界面显示的同步范围；无需重复导出 Journal。
  旧周没有记录时显示空态，不推断曾经未佩戴或同步失败；已有同步断点仍按原窗口恢复。
- 每项趋势显示窗口内已采集记录的最早/最晚日期、有记录的 UTC 日期数、记录条数及有效观测数。
  日期范围不保证每天都有记录，也不能用于推断佩戴天数；同日多次训练按多条记录、一个日期计数。
- 7/30 天指最近 7/30 个 UTC 日期，含今天的已发生部分；恢复归属关联周期开始时间。
  曲线保留单条官方观测，同日多次训练不压成“官方日均值”；无记录日期和未评分观测断开。
- 点击概览/表格的「来源」或曲线观测点，查看官方原值、测量区间、来源更新和本地采集/获知时间。
  均值和前后半窗口差值明确标为本应用描述统计。
- 无记录、等待评分、无法评分、校准中和未提供指标分别说明；没有有效观测时不画零值曲线，
  也不提示“再同步即可产生评分”。统计只使用有效观测，前后半窗口缺少样本时提示不足。
- 打开时检查一次：所选窗口及待补取范围在 30 分钟内有适用的成功请求就复用本地副本，否则按需同步六类资源。
  此阈值是本应用策略，不代表 WHOOP 的更新频率；记录少、未评分或无训练不会触发额外重试。
  切换 7/30 天只更新视图和提示，可点击「同步并补取」更新；页面停留时不定时采集。
- 长时间没打开时，以成功请求的区间合并结果定位待补取起点，不以最新健康记录或完成时间推断进度。
  一并重查该起点附近 7 个 UTC 日历日，最多回查 366 天；无可用成功起点（包括记录已到期）时，
  回查最近 366 天并提示更早历史未核查。空记录或尚未评分也可构成成功请求，不要求先佩戴满 30 天。
  366 天是自动查询上限，独立于按采集时间计算的保留期限；官方日期查询并非修改事件流，
  不保证窗口外旧修正或删除都已捕获，也不因返回缺行而删除本地记录。
  每次最多处理 100 页、整批最多 10,000 条，达到限制会保留断点，继续使用已有恢复入口。
- 已有未完成同步时暂停自动尝试。「继续上次同步」保留原请求窗口；
  「重新同步并补取」按最新状态重新计算范围并新建请求。过期断点清理后需重新同步；未授权时按提示在本机恢复连接。
  同步状态不代表每天覆盖完整；数据只有整批校验通过才入库。
  「最近成功请求范围」只表示成功请求的边界，与当前所选指标实际有记录的日期范围分开展示。
  同步失败后仍可查看已有数据及来源；切换窗口不会清掉同步失败或状态查询错误。

无需凭据的合成演示使用单独数据库：

```sh
uv run whoop-copilot dashboard --demo
```

看板只接受 `127.0.0.1` 同源访问，真实环境只读取已有获准 SQLCipher 库。
Chart.js、脚本、样式均随包本地提供，无 CDN、统计追踪或真实数据 WebMCP。
浏览器会话失效或服务重启后刷新页面。默认 MCP 继续仅开放合成环境。
浏览器中已显示的内容会保留到关闭或刷新；来源到期清理不会远程擦除一个已打开的页面。

F2.1 已用合成数据在浏览器验收窗口切换、来源详情、空态、同步成功/失败/续传，以及窄屏布局。
F2.2 增加按需更新、新鲜度、失败恢复与授权门控；验证范围见 [实施状态](../STATUS.md)。
F2.4 摘要随已有视图读取/同步完成更新，页面不新增定时采集、日报任务、模型外发或报告归档。
F2.3 的「日志时间线」按日志所标日期查看 7/30 天问答，每页最多 20 条，并列该日范围内最近的
官方恢复分、睡眠表现与周期负荷；日期/时区及两类来源均可核查，空白回答不当作“否”。
「同步数据」只更新 API 指标；Journal 需通过本机 CLI 导入官方 CSV/ZIP 后点击「刷新日志」。
Journal 是可选补充，不是日常步骤；当前没有官方 Journal 自动接入，后续主线不等待日志文件。
示例 mapping 的列名全部为合成，不能未经核对直接用于真实导出。实际导入兼容性仍待验收。
开发者可运行 `uv run python tests/dashboard_scenarios.py --scenario short-history --port 8767`
复现；`--help` 列出其余场景，数据为临时合成库且不访问 WHOOP/Keychain。
用户已反馈本机真实记录与 WHOOP App 抽查一致；全部历史逐条对账另行验收，记录不包含真实健康内容。
