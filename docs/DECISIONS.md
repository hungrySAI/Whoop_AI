# 项目决策

日期：2026-09-07。状态：D01–D10 始于 F0，并按实现修订；D11 记录本地运行方向，D12–D13 为 F1 接入方案，D14 为 F2 看板实现。它们限定工程方案，不将后续范围视为永久禁令，也不代替验收。当前结构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## D01：一个 Python 单体与一个 SQLite 数据库

采用 Python 3.11+，将接入契约、存储、分析、操作与入口放在一个包内。SQLite 同时保存源版本、规范记录、证据、训练计划、批准和任务，避免在最小闭环中引入多数据库一致性和消息总线。领域查询与操作服务独立于 CLI / MCP；F2 本地 Web 入口复用相同服务。

复用 SQLite 事务及 backup API，不自行实现数据库、文件复制式在线备份或双持久层。
F0 建立 schema 1；F1 以明确迁移升级至 schema 2，保留已有版本和分析。

## D02：合成默认与获准真实环境分离（F1 修订）

F0 的合成默认保留。F1 新增本地所有者明确授权后的 `real` 环境，使用 SQLCipher、OS Keychain 和有期限的来源政策。
真实内容不能写入合成库，合成 fixtures 也不能写入真实库；环境标签不能替代来源真实性或授权。

没有凭据时继续以合成内容验证。真实启用需用户主动初始化并登录；2026-09-07 已完成首次实际账号、钥匙串和六资源小窗口联调。
本地存储授权不含模型外发，MCP 保持合成环境。退出后定时清理、独立副本治理和跨设备密钥恢复尚未实现。

## D03：先复用 WHOOP 已有资源，再补本应用的能力

按[WHOOP 官方 OpenAPI](https://api.prod.whoop.com/developer/doc/openapi.json)及[API Reference](https://developer.whoop.com/api/)核对 v2 的 recovery / cycle 字段、单位和状态。F0 映射官方定义的恢复分、HRV、RHR 等；不重写 WHOOP 评分算法，不将本应用的均值或变化值称作官方分数。

F1 复用 Authlib、HTTPX 和固定 OpenAPI 契约，实现必要的 WHOOP 端点适配、分页和同步。
官方 CSV 导出、Coach 等已有能力也纳入产品取舍。资源清单与未核实项见 [WHOOP_RESOURCES.md](WHOOP_RESOURCES.md)
及 [F1 核查](F1_RESOURCE_FINDINGS.md)。未确认有 WHOOP 官方 Python SDK，不把社区包冒充官方。

## D04：独立个人身份与可追溯来源版本

本地个人身份使用独立 UUID，WHOOP 外部用户 ID 保存在 provider 连接和来源元信息中。当前每个 provider 一个连接，满足个人项目而不预建多租户。

源版本保存 payload、内容哈希、解析器版本、来源修改时间和应用获知时间；观测与活动引用该版本。WHOOP recovery 与完整关联 cycle 作为组合来源，使 cycle 时间修正也能进入新版本。普通体重指标可独立接入，不被迫拥有 WHOOP cycle。真实版本受明确保留期限约束；版本化不代表永久保留许可。

## D05：明确区分观测时间与应用当时已知状态

使用 `known_at` 支持 `as_of`，先排除应用后来才获知的资料，再按来源版本选择记录。历史不足明确返回限制，不用当前修正填充过去知识。恢复趋势以 UTC 窗口及 cycle 起点筛选；当前不实现本地日历日对齐。

查询保存输入版本、来源目录位置及计算版本。复算固定使用同一输入与算法版本。F1 到期或明确删除来源时清除关联规范值、分析缓存、任务和受管备份；输入删除后旧分析不可复算。独立副本与系统快照不在传播范围。

## D06：注册的确定性描述统计与 EvidenceBundle

采用指标 / 算法字典注册，当前使用 `mean_change/1` 比较等时间窗口两半均值。数值由代码计算，质量不合格的观测排除，缺失不补零；来源冲突要求明确选择。结果区分 WHOOP 来源指标与本应用派生统计，不声称医学结论、统计概率或因果关系。

EvidenceBundle 保存源版本引用、规范观测、单位、算法版本和限制。暂时无需模型服务、提示词、向量数据库或任意 Python 执行工具；模型缺席时核心查询仍可运行。当前窗口与数量限制是已实现的资源预算，未来按实际需求调整并验证。

## D07：同库持久任务与保守失效

新源版本导入与当前分析失效、重算任务入队放在同一事务内。先保守失效全部当前分析，保留 `as_of` 历史结果，避免过早建设复杂依赖图。

任务通过租约、租约 token 和幂等分析处理重试 / 进程中断；CLI `work` 执行有界批次。尚无常驻调度、外部队列、失败自动退避或实际 WHOOP 后台同步。此结构提供后续 worker 的基础，不将手动命令描述为自动化服务。

## D08：本地训练提案与有范围的批准

草稿、提案、批准和提交分开。批准绑定具体内容哈希、目标、预期版本、scope 与期限，后端生成随机 token 并只保存哈希；提交检查并发版本、撤销及幂等性。计划文本不自动成为已执行运动或用户事实。

CLI 的本地操作者审核后提供完整内容哈希，批准命令可签发 token；MCP 只有提案和持 token 提交，没有批准工具。这个机制依赖本地操作者权限，不提供对同权限 shell、数据库直接访问或恶意本地程序的身份隔离。若需要更强的操作授权，下一阶段须定义并实现独立的可信批准通道。

## D09：采用 MCP 官方 SDK 的明确兼容线

协议层使用[官方 MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)的 `FastMCP`，复用工具 schema、协议处理与 stdio 传输，不自建 JSON-RPC 实现。CLI 和 MCP 调用同一 `CopilotService`、`CommandService` 与指标注册表。

`pyproject.toml` 的兼容范围为 `mcp>=1.26,<2`，`uv.lock` 当前固定解析为 **1.29.1**。这是明确选择的 v1 兼容线，不声称是官方 SDK 的最新版本。升级到 v2 需要单独评估 API 变更及协议兼容，不能仅修改上限后继续沿用旧版接口。

## D10：保留审查输入，分别记录实现与验收

初始审查、基础规格和修订任务统一保留在 [2026-09-05 审查目录](../reviews/2026-09-05/README.original.md) 作为来源材料；初始 README 同目录归档。新实现说明与运行入口不抹掉原审查结论。本文不替代验收记录，也不把设计要求、实现存在、测试执行和真实客户端接入混为一谈。

F1 新增保护及接入机制的合成验证，不将其当作真实账号或生产验收。F2 实现本地 Web；用户上下文、模型与外发和部署保持后续范围。

## D11：Dashboard 先本地运行，云部署后续再考虑

2026-09-05 用户确认先在本地运行，以后再考虑部署到云服务器。后续 Dashboard 以本机浏览器访问、本机应用服务与 SQLite 为默认方案，复用现有共享服务，保留迁移到单台云主机的能力。

当前不为未来上云提前拆分服务或更换数据库；云资源与远程访问在用户后续决定时再规划。
2026-09-07 用户批准动工，F2 第一版已实现，具体范围与验证见 STATUS.md；本地授权不含上云。

## D12：官方导出显式映射，API 固定契约

官方未完整公开导出表头/时区/单位，采用结构检查与用户明确映射，避免猜列名。
导出身份来自指定稳定列，来源为 whoop_export，与 whoop API 不自动合并。
API 使用原样 OpenAPI 快照及 SHA-256 检查；六资源完整原文保留，选定标量规范化。
周期与单次训练同名指标需明确资源过滤，profile/body 未提供测量时间时不伪造观测。

## D13：成熟加密与授权库，有限本地保留

使用 SQLCipher 引擎及社区 sqlcipher3 包装，OS Keychain 保护密钥/凭据，Authlib 处理 OAuth。
通过模拟响应验证 HTTPX 兼容路径，局部处理 Authlib 的已知导入弃用提示以保持 CLI JSON 输出。
API 期限从页面采集起计算，文件导入从本地接收起计算；暂存规范化与重复导入不延长原版本期限。
领域获知时间仍是原子入库时刻；删除传播到规范值、分析及受管备份，恢复不重置期限。
无常驻清理器、外部副本追踪或生产灾难恢复声明。

## D14：薄本地 Dashboard，复用评分、统计和同步

F2 采用已在项目依赖树中的 Starlette/Uvicorn（现直接声明），以及本地随包 Chart.js 4.5.1（MIT）。
依照 [Chart.js 官方集成方式](https://www.chartjs.org/docs/latest/getting-started/integration.html)使用 UMD，
不为单页本机界面新增另一套构建、数据库、云托管或认证账户。
原生语义 HTML 和 dialog/table 控件承载页面，Python 共享服务负责全部健康数值与来源版本。

只实现用户批准的概览、六指标 7/30 天趋势、来源详情及手动同步状态。
官方分数不重算；缺失/未评分不补值；周期和训练负荷分开；应用均值明确标注。
复用 Authlib/HTTPX/SyncService 完成真实刷新与同步，保留 SQLCipher/Keychain 政策。
本机 HTTP 要求同源、会话及同步 CSRF，资产不访问外部 CDN，没有公开端点或真实 WebMCP。
F2.1 已用合成场景完成浏览器交互与视觉验收；用户已反馈真实 App 抽查一致，全部历史对账仍单独验收。

## D15：覆盖元数据不推断佩戴历史

请求范围、当前记录日期范围、有记录日期数、有效样本和同步结果分别表达。
记录日期按 UTC 去重，同日多次活动不增加日期数，日期跨度不替代实际有记录日期数。
最早现存记录不自动认定为佩戴首日，日期范围也不保证连续有记录；不按无记录天数判断漏同步。
复用 WHOOP 官方评分与校准字段，已有未评分记录不要求重复同步以产生评分。
浏览器验收使用独立临时合成库和模拟同步客户端，同一用户标签验收结束后恢复到原本机地址。

## D16：按需更新以成功请求为依据，失败由操作者恢复

2026-09-07 用户批准 F2.2。打开时检查一次，30 分钟内适用成功请求可复用；这是应用策略，不是 WHOOP 更新承诺。
WHOOP 官方评分、分页、OAuth 刷新、限流处理继续复用现有实现。共享锁内复查持久状态，客户端在断点创建后初始化。
未完成任务不因刷新/切换窗口重试；续传保留原查询，重新同步使用当前窗口。授权不明或已失效时禁用采集。
运行中只轮询本地状态；前端可在新鲜度阈值到达时更新文案，但不定时请求 WHOOP。
页面关闭不再触发检查；已发起的有限同步仍可由本地服务完成。服务退出后已有断点可恢复。

## D17：复用官方 Journal 导出，明确日期和本人归属后展示

2026-09-07 用户批准 F2.3。官方导出提供 Journal，当前六资源 API 适配器不读取日志，
因此扩展既有 CSV/ZIP mapping，而不创建抓取器或重建 WHOOP Journal。
mapping v2 明确问答、日期/时间精度、稳定身份与操作者确认；不猜真实表头，也不将确认视作 OAuth 账户验证。
日期级日志没有虚构测量时间，只用明确时区的当日边界并列已有 API 指标；不重算评分或声称因果关系。
原始行与归一化问答共享源版本、SQLCipher 和生命周期，HTTP 仅投影当前版本所需字段。
浏览器只读，本地 CLI 主动导入；API 新鲜度与日志导出/导入时间分别表达。
本批代码和合成验收不代替实际文件联调。没有新导出中的旧行不自动构成删除；原始下载不纳入受管清理。

## D18：日常价值不依赖用户反复搬运文件

2026-09-07 用户指出，定期手工导出/导入 Journal 违背使用初心。修订 D17 的产品优先级：
保留已实现导入作为可选历史补充，暂缓真实文件验收，不将缺少文件视为主线阻塞或要求用户持续维护。
日常主线优先使用已授权官方 API 可自动获取的数据，复用 WHOOP 指标及既有本地服务。
当前公开 API/webhook 尚未核实到 Journal 自动读取能力；下载目录监控不能替代上游自动获取，
不以此宣称完成自动接入。后续若官方开放相关能力，再按实际需求评估，当前没有监控任务。
下一批可考虑已有指标的本地每日摘要与短期变化，具体实现范围另行确定。

## D19：每日摘要复用官方概览及注册统计

用户批准 D18 所述下一批后，F2.4 在原 overview 的一致性读取内投影三项每日摘要，
复用三卡的当前记录、mean_change/1 结果与 analysis_id，不新增健康算法、查询端点、表或外部服务。
每天查看不等于三项测量发生在同一天，保留各自 UTC 日期；未评分不回退旧值，
睡眠不擅称昨夜主睡眠，开放周期的当前负荷不称全天最终值。
前后半窗口至少各两条有效观测才输出高/低/相同，数值不足时即使原算法有差值也不做摘要结论。
变化只作描述统计，不等于健康改善或行为影响；点击可复用已有趋势与来源入口查看依据。
没有独立日报归档或后台生成任务，打开时的既有条件同步仍是唯一自动采集触发。

## D20：周回顾按当前保留记录计算

用户继续批准下一步后，F2.5 将路线中的周报先实现为可反复查看的本地周回顾。
默认上个完整 UTC 日历周，可选择最近 12 周；比较复用连续 14 天 mean_change/1 的两个等长半段，
本周仅展示进度，两周各不足两条有效样本时不输出比较。短历史与无 Journal 均可使用。
复用现有官方指标、规范观测、来源详情和六资源同步，不引入新评分或定期人工导出。
查看明细时同步刷新整张周表，保证官方修正、删除、到期或跨周一后各部分使用同次读取结果。

不另存永久周报副本，因为这种副本需要独立保留/删除治理，也不能保证现有短历史的完整性。
周回顾随当前保留来源更新，删除和到期仍遵守现有生命周期；日历周结束不代表每天采集齐全。
选周不触发网络，更新按钮仍请求最近 30 天，界面明确更早周不会因此回填。
永久归档、后台生成与发送周报仍需后续具体需求和范围；本批不增加常驻调度或外发。

## D21：恢复回看使用官方身份关联

用户要求继续下一步后，F2.6 优先实现已有数据的可追溯回看：同一周期的恢复、官方关联睡眠和周期负荷。
官方 ID 和评分字段已经由现有同步提供，因此不另造同日/最近记录匹配、评分模型或额外采集协议。
睡眠允许跨查询窗口，nap 独立保留；训练没有官方 cycle_id，不按本地相邻时间强配。
恢复的内嵌周期和当前周期不一致时明确提示，避免把旧观测的时间静默改成新周期。
UUID 大小写只在连接时规范化，存储和证据原文不改；规范化后冲突保持歧义。

一页返回有限的完整关联投影，列表和选中详情共用同一读取，不新增本地报告表。
使用已有的恢复三指标、睡眠四指标与周期负荷，保留未评分、缺失和小睡；不作因果、疾病或活动建议。
日常操作无需新增 Journal 导出或个人填写。模型、后台生成和独立报告归档仍保持后续范围。

## D22：按使用时机补取，暂缓后台定时同步

用户于 2026-09-07 说明每天关机、周末可能不开机，并明确批准 F3.1 启动体验与长间隔补取。
复用 WHOOP 云端可查询的历史，电脑只在用户需要时运行本机服务；不安装 launchd、登录项或定时任务。
打开/停止脚本调用同一 Python CLI，通过私有身份验证确认服务属于当前项目/数据库后打开浏览器或请求停止。

SyncService 在原跨进程锁内清理到期，再合并保留的成功请求区间；从最早已知断开处向现在补取，
而不是让较新的窄窗口请求掩盖旧空档。无空档时从连通区间终点回查附近 7 个 UTC 日历日，
并至少覆盖所选 7/30 天视图。请求结束时间而非完成时间决定进度，未来时钟的记录不能证明已同步。
自动查询最多回查 366 天，来源于现有单次同步窗口上限，是应用策略，不是 WHOOP 的历史保留承诺。
成功请求记录全部缺失/到期时同样进行 366 天有限回查，不把它称作首次佩戴或全量历史同步。

该范围独立于 LocalPolicy 按采集时间计算的保留期限，新采集仍按原政策到期；不保存额外永久水位表。
规划信息放在既有 sync_runs.state，与原暂存页和断点一起过期/删除/受管备份清理。
仍在断点创建后构造 OAuth 客户端，100 页有限批次、10,000 条上限、六资源整批校验及幂等继续复用。
打开时一次条件检查与 30 分钟复用阈值不变；未完成断点需要明确继续或重新同步。
WHOOP 的发生时间查询不是 updated_since，重查只能发现返回范围内的修正，缺行不能视为删除。
F2.5/F2.6 文档中的固定同步窗口是当时版本行为；当前按需同步以本决策为准。

## D23：恢复副本只管理自己后续创建的备份

F3.2 验收发现，backup 把源库 managed_backups 登记一起写入快照，旧版 restore 原样复制这些路径，
导致恢复库的到期或删除操作可能清理原库的备份。0.4.1 在复制到目标后清空该登记，并复查目标完整性。
登记清理只发生在恢复目标，不改变源库登记或源备份，所有其他表与源期限保持一致。
恢复库可登记自身新建备份并按原生命周期清理；schema 1 的合成恢复路径不访问不存在的登记表。

真实演练在同机私有临时目录中用独立 OS Keychain 密钥重加密，源库停止服务并持同步锁，
固定演练时钟对比全部非登记表、概览/周回顾/恢复回看结果与期限。只有副本执行来源删除。
演练后移除本次专属登记/文件与临时密钥，原库、原有备份和原密钥验证不受副本清理影响。
这不是跨设备密钥备援、整机重启、云备份或生产灾难恢复的验证，也不保留额外永久副本。

## D24：数据稳健性加固与兼容迁移

用户批准修复独立审查中的六项问题。0.4.2 / schema 3 保留既有 Python/SQLCipher 架构与采集期限。
入库把清理、判重和版本写入放进同一事务时刻；当前版本到期时，同身份前驱可早于自身最长期限失效，
避免把旧修正或删除前记录重新当成当前数据。更晚但从未成为当前的旧资料不被提升，其他身份期限独立。
不以保留超期删除标记或给重复版本续期来处理该问题。

分析发布和读取在事务内验证输入版本仍存在、哈希匹配且未到期；显式历史分析也不能重建已清理内容。
日常 Dashboard/周回顾/Journal 并列指标即时计算，使用同一注册算法和精确窗口，analysis_id 为 null；
明确 CLI/MCP analyze 继续保存可复现证据。历史缓存没有可靠的页面/显式来源标志，不能猜测其用途清除。
显式缓存以请求、输入版本、首次知识时间、算法和单位为键；无关 profile/body 采集不复制健康分析。
有关来源/资源/指标变化才失效，待处理请求去重且每批最多 100 个；运行中的任务必须保留后续修正。
旧超预算任务明确失败，不静默部分执行；日常请求不再产生这类任务。

WHOOP sleep/workout 在解析、直接入库和关联前统一 UUID；原始 payload 和原 content_hash 不重写。
source_ingest_keys 提供独立规范重放键，外键跟随源版本删除；旧别名合并保留所有历史 ID 和规范观测。
迁移调整逻辑身份时间线，原分析若引用受影响版本则清除重算；同来源时间戳下删除状态优先。
新库直接 schema 3，旧库事务迁移；schema 1 合成及 schema 2/3 加密备份继续可恢复，副本不继承原备份权限。

新同步拒绝未来结束时间，旧成功区间仅以 min(请求截止、创建、完成) 证明覆盖，时钟回拨保护保留。
查询先选择当时/当前胜出版本再筛测量日期；资源筛选和版本聚合下推 SQL，仅加载胜出原文，补齐关联索引。
不新增后台同步、云资源、Journal 日常输入或健康数据外发。历史轮查和删除信号接入仍是单独能力边界。
