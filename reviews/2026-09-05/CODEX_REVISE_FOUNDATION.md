# 发给 Codex：审查后修订架构，并验证最小基础

你现在继续 WHOOP Personal Copilot。我的产品方向没有改变：WHOOP 已开放的核心数据尽量全覆盖，日常分析与教练用途尽量做完整；WHOOP 负责采集、官方计算和设备操作，外挂负责长期趋势、追问原因、训练管理和其他身体信息整合。

我对早期架构的补充要求是：**不要用过多产品限制封死后续玩法；先把可扩展、可信、可复算、可受控操作的根基做好。** 这不是让你关闭安全控制，也不是让你一次建设大型平台。

## 1. 先审计，不推翻已有成果

检查当前工作目录、Git 状态、现有实现和测试；保留我的未提交改动，不扫描其他项目或个人目录。

读取原根目录 `AGENTS.md`、`PROJECT_CHARTER.md`、`ROADMAP.md`、`STATUS.md`、有关架构／数据／教练／安全／验收文件，以及本审查包的 `ARCHITECTURE_REVIEW.md`、`FOUNDATION_REVISION_SPEC.md`。本包可能位于 `reviews/2026-09-05/`；若未找到，只在当前项目内定位，不假装已经读过。

原包与实际代码不一致时，以实测事实为依据。此审查主要针对 v1.0 文档，不证明你当前代码也有全部问题。逐项确认适用性，不照单制造重构。

## 2. 本轮明确变更的项目规则

以下是我对旧项目规则的修订授权；先统一修改原有权威文档，再实施，不要追加一份与根 AGENTS 冲突的规则。

1. WHOOP 源记录仍只读；本应用的日志、计划、反馈和草稿允许通过共享命令服务受控写入。不是所有 MCP／模型工具永久只读。
2. 数值由代码计算，不等于模型只能复述固定报表。允许模型提出受约束分析请求、比较假设、调用新注册计算，并记录探索结果。
3. WHOOP 是第一个提供方；在数据和服务契约中保留其他获准来源的位置，但本轮不做一堆空连接器。
4. 保留单用户模块化单体，不预先建设 SaaS、微服务集群、完整事件溯源、插件市场或多代理管理平台。
5. 按依赖做小型纵向交付。旧“M0 绝不允许代码”“必须全部 M3 界面后才做 Codex”“每个跨层改动都另等阶段批准”的机械限制不适用于本轮获准闭环。
6. 权限、真实数据、外发、费用、部署和不可逆操作仍按明确范围控制；不要擅自扩大授权。

## 3. 本轮交付 A：统一修订基础设计

审查发现不能只改 `ARCHITECTURE.md`。请同步更新有冲突的 `AGENTS.md`、章程、路线、状态、数据契约、分析规范、教练规范、安全规范、验收、配置示例、阶段提示词及运行教练提示词。

不要求为每个新概念新建文档。指定各规则的权威位置，其他地方引用，避免继续复制互相矛盾的政策。原测试／实施历史保留；用决策记录说明哪些旧要求被替代。

具体要求：

- 用最小 SourceConnection／SourceRecordRevision／Observation 和具体活动模型明确来源、内部身份、时间、单位、状态、去重与版本。不要一个万能 JSON 表，也不要过早通用化整个医学领域。
- 明确查询服务、可组合分析服务、上下文服务和命令服务；Web／CLI／MCP 只做入口适配，不复制业务逻辑。
- 计划／日志动作需有幂等键、目标版本、范围、确认及审计。审批不能由模型自己传 `approved=true` 伪造；客户端的只读提示也不代替服务端权限。
- 稳定分析与探索分析分开。早期用有类型请求和注册函数；任意生产 SQL、全电脑 Shell 或全权限代码执行不是扩展性方案。
- 个人事实、目标、限制与模型假设分开；记录生效／确认／失效时间和建议反馈，不引入不必要的向量数据库。
- 让授权按目的、接收方、字段、范围、操作、期限与预算持久化；范围内不重复询问，扩大范围才再确认。
- 把幂等、版本、最小任务状态、迁移和保护措施前移到第一批持久化实现；高级自动化可后续完善。
- 修复 `.gitignore` 的 `imports/`、`data/` 等非根限定模式误伤源码／fixtures 的问题。保护真实数据，不取消秘密防护。
- 实際核查 WHOOP API Terms of Use 的存储、外发、保护与用途边界，记录未决项。不要断言私人项目被禁止，也不要断言个人 OAuth 自动授权无限存档／所有官方派生数据再利用。合成原型可以继续，不擅自启用有疑义的真实用途。

## 4. 本轮交付 B：一个最小可运行的基础闭环

不只写文档。使用独立合成环境和一个选定数据库，实现或增量补齐一个小闭环：

合成 WHOOP 样本 → 源版本与规范化存储 → 一项确定性趋势分析 → 可追溯 EvidenceBundle → 一个真实服务入口。

在同一闭环中验证三个扩展接缝：

- 用普通手工／CSV 身体指标适配器证明第二来源不需要改 WHOOP 同步器；不声称这是已接入 HealthKit 或其他真实平台。
- 用训练／日志草稿和确认提交操作证明外挂可写、WHOOP 源仍只读；确认篡改、过期、版本冲突和重复提交有测试。
- 修改一条合成源记录，证明旧派生结果失效、同一输入版本可重算；保存最小持久任务状态并验证重启／重复处理。

尽早给出 MCP 的最小工具连接或协议测试。真实 Codex 客户端未测通时，只能写“协议／合成测试通过，客户端联调未完成”。本轮不需要完整看板、全部 WHOOP 资源、所有分析算法或完整实验沙盒；这些进入后续工作批。

若仓库已经有这些能力，不重建，只补缺口并证明。可以在项目隔离环境安装实际需要的依赖并锁定，不修改系统全局配置，不为选型反复重装。

## 5. 明确许可和停止边界

本轮允许：当前项目文档与代码改动、合成数据库、隔离依赖、测试、必要的官方资料核查。

本轮不自动授权：访问真实 WHOOP／健康数据库、读取个人目录寻找密钥、真实模型付费调用、外发个人数据、公开网络入口、创建云资源、修改其他项目、删除生产数据、推送或发布。

已有明确授权可以按记录使用，不能仅凭存在一个 Key 就推定所有用途都获准。缺少真实凭据时继续合成工作，不停住整个项目，也不制造真实联调通过。

本轮完成 A 和这个小型 B 后交付，不自动扩到所有功能。停止是因为本轮闭环已完成，不是机械沿用旧阶段墙。所有实际工作发生在当前执行会话；不虚构后台持续工作。
